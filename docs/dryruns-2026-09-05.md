# Laguna multi-agent dry runs — 2026-09-05

Three parallel Laguna (poolside/laguna-s-2.1-free via command code) subagents executed
dry runs of the full ScenarioChef pipeline (C1→C10 + CX) with the **real LLM-backed C2
proposer**, esmini 3.7.2 simulation, and the C9 explore loop. One additional offline
control run isolated what the LLM contributes.

**Driver:** `scripts/dry_run.py` — loads `./.env` (quoted values, shlex-parsed) into the
process environment, drives `cx_orchestrator.run_request` with a run-scoped C10 store,
copies the esmini `--csv_logger` states CSV out of C7's temp dir, and writes
`summary.json` + `trace.log` per run under `tmp/dryruns/` (git-ignored). The API key is
only ever read into the process environment — never printed, logged, or persisted.

**Execution notes.** The Laguna upstream returned 503 (overloaded) twice, killing two
subagent sessions mid-flight (their completed runs survived on disk; interrupted runs
were reconstructed from their persisted C10 stores). A summary-clobbering bug in the
driver (shared out-dir) was found and fixed during the session; runs now write into
per-run subdirectories.

## What the Laguna C2 proposer did

- Every LLM run: confidence 0.9, no unknowns, all slots `llm_proposed`, schema gate passed.
- A1: extracted follow + brake (`duration_s=3`, `start_delay_s=5`, `deceleration_mps2=5`).
- B1/B2: produced real lateral intent — `lane_change(direction=left, start_time_s=4)` and
  `cut_in(target_lane_id=1, speed_mps=22)`; C5 compiled them to `LaneChangeAction` /
  `AbsoluteTargetLane` in the .xosc and C6 S1–S4 passed.
- B3: extracted a pedestrian actor (kind pedestrian, 1.4 m/s) with a perpendicular
  `cross_path` maneuver — the ego simply never caught up with it in 30 s.
- C3: decomposed stop-and-go into **5 sequenced maneuvers** (two speed changes each side
  plus follow). Structurally correct; the run collided mid-deceleration so the completion
  objective failed.
- C1 vs C1-OFFLINE isolates the LLM's value: the offline null proposer ignored the request
  numbers entirely (defaults 15/15 m/s, 50 m, lane −1) while Laguna extracted 20/8 m/s and
  35 m from free text. The offline run also lost `ESMINI_BIN` (it skips .env loading), so
  it recorded `skipped_no_binary` — consistent with its offline contract.

## Bugs and findings

1. **C8 collision false positive (fixed).** `compute_metrics` unpacked the `(t, gap)`
   series in the wrong order — `min(gap for gap, _ in gap_series)` compared the minimum
   *timestamp* (0.0) against the 0.5 m collision threshold, so every run with state data
   reported `collision=1.0`. The dry runs caught it: B2's raw state log shows a minimum
   inter-actor gap of 25.0 m and B3 40.0 m, yet both were flagged as collisions. Fixed in
   `src/scenariochef/c8_evaluation/runtime.py` (unpack `(t, gap)` correctly) with a
   regression test (`test_no_collision_when_actors_stay_apart`); full suite: 160 passed.
   All summaries in `tmp/dryruns/` were re-evaluated with the fixed code.
2. **C1 parameter vocabulary is narrow (guardrail observation).** `lead_deceleration` is
   not in C1's `ALLOWED_PARAMS`, so A2/A2B/A3 never reached C2 — CX raised a
   MISSING_PARAM HITL at the input gate. Notably the intended S4 physical-bounds test
   (−50 m/s²) is currently unreachable through this route; C1 needs a deceleration slot
   (or S4 needs to see the value first) for that stress path to exercise C6.
3. **Speed-action semantics in esmini 3.7.2 (visual artifact, not a pipeline bug).** The
   compiled standalone `SpeedAction` snaps the actor to its target speed at t≈0.1 s
   instead of ramping; states CSVs show speed 0 immediately after the first frame while
   positions still integrate. The C9 explore loop then drives the ego into the lead in
   most follow scenarios (that is the loop's job: find the critical configuration).
4. **Laguna upstream 503s.** Two subagent sessions died to upstream overload (the same
   503 the C2 proposer retries internally with backoff). Persisted artifacts made every
   completed run recoverable; no run was lost.
5. **Driver summary clobber (fixed).** The original driver wrote `summary.json` into a
   shared out-dir, so a later run overwrote an earlier one. It now writes per-run
   subdirectories; earlier runs were reconstructed from their C10 stores.
